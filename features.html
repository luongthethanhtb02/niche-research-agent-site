Feature Overview

This page describes functionality implemented in the Niche Research Agent codebase. It is technical documentation, not a live dashboard or public application interface.

Current Implementation Status

The acquisition, normalization, eligibility, orchestration, metrics, and sampling-quality modules have been exercised with deterministic fake or recorded providers. The official YouTube Data API adapters are implemented, but no live sampling pilot has been run. Live network access remains blocked unless the fail-closed compliance gate receives the required authorized configuration.

Implemented Workflow

The implemented workflow is:

  1. A versioned structured niche definition provides the niche description, included and excluded topics, seed queries, language, market, analysis window, baseline window, and sampling limits.
  2. A deterministic query planner creates categorized, deduplicated queries without using a live language model.
  3. The official provider adapter maps video discovery to YouTube Data API search.list.
  4. Discovered video identifiers are deduplicated with query and page provenance preserved, then hydrated in bounded batches through videos.list.
  5. Associated public channel records are deduplicated and hydrated in bounded batches through channels.list.
  6. Eligible relevant channels may be expanded through bounded pages of the public uploads playlist using playlistItems.list. Each discovered upload is separately hydrated and evaluated.
  7. Provider records are normalized into versioned canonical video and channel records without converting unavailable values into zero.
  8. Videos receive deterministic format, niche-relevance, and dataset-eligibility decisions. Only confirmed long-form, relevant, in-window records with required metadata enter the MARKET dataset.
  9. Historical, relevant, confirmed long-form records are independently evaluated for the BASELINE dataset. MARKET and BASELINE records are isolated and deduplicated.
  10. The metrics engine calculates observed volume, distribution, channel concentration, views-per-day, views-to-subscriber ratios when denominators are available, breakout indicators, new- and small-channel indicators, breadth, and data-quality metadata.
  11. The sampling-quality evaluator calculates query diversity and yield, overlap, eligibility funnel, channel diversity, expansion contribution and contamination, saturation evidence, profile stability, sensitivity, bias indicators, warnings, and deterministic sampling confidence.
  12. Deterministic acquisition, canonical-record, dataset, metric, sampling-quality, warning, and provenance artifacts can be written for audit and review.

Data-Access Safeguards

  • The live provider implementation is limited to public data requested through official YouTube Data API endpoints. Offline tests use fake or recorded transports rather than external collection.
  • The project does not request OAuth access or private YouTube user data.
  • The project contains no scraping, browser-based YouTube collection, or competitor-video download path.
  • The ComplianceGate defaults to not configured and rejects network authorization unless an allowed state and approval reference are both present.

Request and Processing Controls

  • Search, batching, pagination, channel expansion, total physical requests, quota consumption, and retry attempts are bounded by explicit configuration.
  • Logical search-page progress is tracked separately from physical provider attempts. A retry does not consume another logical page slot, but it consumes another physical request and applicable quota unit.
  • Provider responses pass through raw snapshot persistence before normalization. Request provenance, discovery provenance, missing records, exclusions, warnings, and partial failures remain explicit.
  • Raw provider responses are written as content-addressed audit records to preserve provenance and reproducibility during the permitted retention period. Cache entries have configured fresh, refresh-needed, and expired states, plus invalidation and expired-entry purge operations.

Classification and Dataset Safeguards

  • Format classification supports LONG_FORM, SHORT, and UNKNOWN. Missing, malformed, low-confidence, or conflicting evidence can remain UNKNOWN instead of being forced into the long-form dataset.
  • Niche relevance supports RELEVANT, NOT_RELEVANT, and AMBIGUOUS. AMBIGUOUS records do not enter MARKET or BASELINE datasets and can be routed to an independent review boundary.
  • Channel expansion does not assume that every upload from a relevant channel is relevant; every upload is classified at video level.
  • Duplicate discoveries preserve their discovery history while contributing only one record to a final dataset.

Observed Metrics and Sampling Boundaries

Observed view metrics use current lifetime view counts on eligible videos published within the configured MARKET window. They are not represented as views generated during that window, a total YouTube market estimate, or a market-coverage percentage.

The metrics engine does not create a final niche score or PASS, WATCHLIST, or REJECT recommendation. Sampling confidence evaluates the quality of the collected sample, not whether the niche is attractive.

Retention and Current Limitations

Implemented cache controls support time-based refresh, expiry, invalidation, and purging of expired cache entries. Raw provider-response persistence exists for provenance and auditability, but the end-to-end retention and deletion lifecycle for those persisted records has not yet been validated for live operation. Live operation will remain blocked until retention, refresh, and deletion behavior is aligned with applicable YouTube API Services policies and any required permissions or approvals.

No live pilot, live API result, production metric, or compliance approval is presented on this page.
